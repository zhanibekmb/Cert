## Тема 1 — Наказание + что такое «день»

### Найденные проблемы в коде
1. **Нет сброса за пропущенный день.** Нет cron/фонового прохода. Стрик меняется
   только на сабмите (`server/index.js:58` `applyVerdict`). Перестал слать фото →
   стрик застывает и врёт. Это ломает обещание «нельзя подделать».
2. **Два клиента наказывают по-разному.** Сервер: 3 страйка → сброс (`index.js:66`).
   Мобайл: один отказ сразу обнуляет (`App.js:1137`). Рассинхрон.
3. **Баг двойного счёта.** `streak += 1` без проверки «уже засчитан сегодня»
   (`index.js:62-63`). Два фото за день = +2.

### Решение
- **День** = локальный календарный день пользователя (таймзона уже хранится:
  `App.js` профиль, `daily_deadline` на цели). Дедлайн на цель опционален
  (`daily_deadline`, уже есть в UI создания цели).
- **Один зачёт в день.** Фикс бага: в `applyVerdict` инкрементить только если
  `goal.last_submit !== today`. Повторные сабмиты в тот же день не двигают стрик.
- **Триггер наказания = пропущенный день.** Нужен серверный ночной проход
  (cron / scheduled function): для каждой активной цели, если за вчера нет
  approved-сабмита и день прошёл за дедлайном → `streak = 0`.
- **Единое правило для обоих клиентов:** пропуск ИЛИ финальный отказ → стрик в 0.
  Свести мобайл (single-reject) и сервер (3-страйка) к одному. Рекомендация:
  отказ можно переснять в течение дня (страйки как внутридневные попытки), но
  конец дня без зачёта = сброс. 1 апелляция/мес восстанавливает (из CONCEPT §B).
- **Вечный счётчик** (ключевой инсайт): `verified_days_total` и `best_streak`
  НИКОГДА не обнуляются. Брутальный сброс переносим, потому что заработанная
  история не уничтожается. Это и есть подушка против оттока.
- **Freeze** — платный слой (CONCEPT): N заморозок/мес у Pro авто-защищают
  пропущенный день в ночном проходе.

### Что трогать
- `server/index.js:58-71` — `applyVerdict`: гард «один зачёт в день».
- Новый серверный scheduled job (пропуск → сброс, учёт freeze).
- Supabase-сторона мобайла — тот же гард + ночной проход (Edge Function / pg_cron).
- Схема: `goals.verified_days_total`, проверить что `best_streak` не сбрасывается
  (`db.js:49-50` уже есть `best_streak`).

## Тема 2 — Статистика

### Решение
- **Герои экрана (только растут, никогда не падают):** verified days total,
  best streak, текущий стрик, заработанные certs/badges.
- **Честность как теплокарта, а не процент-приговор.** Календарь GitHub-стиля:
  зелёный = зачёт, красный = отказ, серый = пропуск. Те же данные, что «62%
  выполнено», но заливать сетку мотивирует, а смотреть на процент — нет.
- **Линия free/paid:** Free = герои-числа. Pro = теплокарта + разбивка по целям
  + тренды. (CONCEPT: аналитика — платная.)

### Что трогать
- `mobile/App.js` `computeStats` (сейчас только `approved`, `bestStreak`) →
  добавить total, теплокарту из `subs` (даты + status уже грузятся: `App.js:359`).
- Экран Stats (`tab === "stats"`) — собрать герои + календарь.
- Гейт Pro на теплокарту/тренды.

## Тема 3 — Видеофиксация + анти-чит

### Что уже построено (mobile/App.js)
- Таймлапс-захват: `TimelapseCapture` (894+), кадр каждые `TL_INTERVAL_MS=3500`,
  `TL_MAX_FRAMES=12`, `TL_MIN_FRAMES=3`, живая камера.
- Переключатель `photo | timelapse` на сабмите (780), Reel-просмотрщик (708), гео.

### Дыры
1. **Фото из галереи без проверки** (`App.js:538` `launchImageLibraryAsync`) —
   главная чит-дыра.
2. **Серверный судья видит один кадр** (`ai.js` `geminiJudge({ photo })`). Клиент
   шлёт 12 кадров — серия не судится.
3. **Экспорт рила в видеофайл не сделан** (`App.js:763`).

### Решение
- **Таймлапс = Pro-фича**, solo и группы, единый движок (текущие 3.5с / 12 кадров).
- **Галерея остаётся**, но фото проходит **freshness-гейт:**
  - EXIF-таймстемп съёмки = сегодня (отсекает старое/чужое);
  - видимый daily-токен (`ai.js:26` `dailyReq` уже есть — судья отклоняет, если
    не видно).
- **Живой захват** — равноправный путь, тот же гейт по содержимому.
- **Стоимость:** таймлапс ~12× Vision на зачёт → судья сэмплит 3-4 кадра, не все
  12; доступ гейтится Pro. Лимит фото/день на free (CONCEPT) сохраняется.

### Что трогать
- `server/ai.js` `geminiJudge` — принимать массив кадров, судить серию (сэмпл 3-4).
- `server/ai.js` — добавить EXIF-проверку даты для галерейных фото.
- `mobile/App.js` сабмит — прокидывать taken-at/EXIF, гейт таймлапса на Pro.
- Экспорт рила в видео (отложено, не блокер).

## Исполнительные задачи (скоуп, не дизайн)

1. **Светлая тема / белый фон.** Рекомендация: тёмная тема остаётся дефолтом
   (серьёзный «судейский» вид; чистый белый делает Cert похожим на дженерик
   to-do). Добавить светлую тему как опцию, уважать системную настройку; если
   белый — не чистый `#fff`, а тёплый off-white. *(решение подтвердить)*
2. **RU-локализация.** Бэкенд уже знает язык (`users.lang`, `ai.js` spec ru/en).
   Задача: i18n UI мобайла (RU/EN) от локали устройства + профиля.
3. **Платёжка.** ⚠️ Stripe в in-app покупках iOS = реджект. Мобайл: **StoreKit +
   Play Billing через RevenueCat** (единый Pro-entitlement гейтит freeze /
   таймлапс / аналитику). Веб: Stripe. Заменить демо-оплату.
4. **Хранение фото + показ друзьям.** ⚠️ НЕ блобы в Postgres. **Объектное
   хранилище** (Supabase Storage / R2), в БД — ссылка + метаданные. Показ друзьям
   = права доступа (привязано к соц-слою / группам = фаза 2).
5. **Инвайт-ссылки.** Реферал частично есть (`genRef`, `ref` в signup
   `index.js:112-122`; `joinCode` `App.js:336`). Задача: deep link → открыть
   приложение (или стор, если не установлено) → префилл joinCode/ref → атрибуция
   рефереру на signup. Веб-фолбэк.
